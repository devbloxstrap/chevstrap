V9 workflow: DISCOVER → AUTO-PAUSE/RESUME → VERIFY → RANK → CLUSTER INTO NICHES. Auto discovery uses GitHub repository search, split across star tiers and pages; verification then sums release assets and inspects install-file signals.
“Opportunity Score” is 0–100 and weighted by the sliders in step 4 (Demand, Growth, Website Gap, Consumer Intent, Freshness, DL/Star, Unmet demand). It is a prioritization score, not a promise of Google traffic.
“Niche score” rolls repos up by shared topic: Demand 30 + Site gap 22 + Consumer intent 18 + Growth 14 + Fragmentation 10 + Unmet demand 6. Fragmentation matters — a topic where one project owns 95% of all downloads is a monopoly and a bad entry point; a topic where demand is spread across five mid-size projects is an open field. Only topics with 2+ verified repos become niches.
Every GitHub response is stored with its ETag. On a re-scan the app revalidates instead of re-downloading, and GitHub does not charge a 304 against your rate limit — so scanning the same list again is close to free.
“Total DL” = every asset across every release, summed live from the GitHub API.
“Latest DL” = downloads of the newest release only, with its share of the all-time total beside it. A high share means demand is live right now, not a leftover from an old version. The date column shows when that release shipped and its tag — click the tag to open it on GitHub.
“DL / month” is the current rate: latest-release downloads ÷ days that release has been out. It tracks demand today rather than a lifetime average — hover any number to see both. A “~” means the release is under 10 days old, so launch-day traffic is still inflating it. GitHub exposes no real download history, so treat every rate as a ballpark; for an exact figure, scan again in 30 days and subtract.
“Web presence” checks the repo homepage plus README links: NONE = strongest site gap; DOCS = docs/GitHub only; README = an external domain appears only in README; DEDICATED = a real homepage is set.
Every scan is saved in this browser automatically and reloads when you come back — no re-scan, no network. “Save scan (.json)” writes a portable copy you can keep or move to another machine; “Import saved scan” reads it back, along with any CSV this app exported. Re-scan an imported list and each row shows what changed since that snapshot. Your token is never saved to a file or exported.
Runs entirely in your browser. Nothing is uploaded anywhere except your own calls to api.github.com.
